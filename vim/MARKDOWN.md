# Markdown 新版目标与开发记录

## 目标与边界

性能是硬约束，编辑体验是中心，渲染保持清楚、克制。运行在原生 Vim 8/9，沿用
TokyoNight；无需插件管理器、特殊字体、Python Vim 接口或网络。

| 模块 | 目标 | 约束 |
| --- | --- | --- |
| 显示 | 标题层级、代码、引用、任务、链接与强调清楚可辨 | 原生 syntax；保留源码布局，不创建全文虚拟文本或窗口 match |
| 结构 | 共享围栏、注释、front matter、标题索引 | 计时器分批；修改回调只标记失效；输入不等待全文扫描 |
| 编辑 | 列表续写、空条目退出、任务、中文表格、选区包装、模板 | 一次操作一次撤销；兼容补全、粘贴；保留 Markdown 尾随空格 |
| 导航 | 标题跳转、目录面板、文内目录、链接 | 按需执行；不在光标移动或状态栏重绘中解析 |
| 预览 | 显式启动、离线浏览器阅读 | 独立进程；未开启时没有同步工作；暂停输入后合并更新 |
| 集成 | 安装、重载、退出、切换文件类型、多窗口 | 归还局部设置和映射；取消失效工作；保留用户配置 |

复杂的占位符引擎、数学自动改写、自动保存和浏览器双向控制不常驻编辑路径。
公式、图表和图片以源码编辑；常用结构提供显式模板。源码／阅读切换只改变 conceal
选项，不撤下或重建全文装饰。表格按命令整理源码，不做依赖窗口宽度的虚拟排版。

## 开发计划

1. 建立有时间预算的共享结构索引与原生显示层，验证代码保护和无修改渲染。
2. 实现编辑、导航、目录、链接与模板，覆盖中文、撤销、粘贴及补全交互。
3. 接入按需预览、安装、帮助与生命周期；验证旧版升级。
4. 建立真实 PTY 延迟基准，覆盖密集文档、长行、长代码块、连续输入与多窗口。
5. 至少三轮测试与测量：功能回归、压力诊断修复、最终重复验收；记录失败与限制。

编辑和后台处理的关系如下：

```text
修改缓冲区 → Vim 原生编辑与撤销 → 只标记结构失效
空闲计时器 → 有待处理按键／处于插入模式时让出
           → 最多约 3 ms／96 行 → 复用状态相同的后续索引
显式命令   → 读取已完成索引 → 执行表格、导航或目录操作
显式预览   → 停止输入 250 ms → 分批取快照 → 独立进程渲染
```

## 性能验收

使用同一机器、同一完整配置，分别开启／关闭新版模块；避免同时运行功能测试或其他
基准。基准从真实按键发送计时，确认 Vim 状态及其后的终端重绘，不只测函数耗时。
输出样本数、中位数、P95、最大值、最长主循环间隔，并保留首次样本。

- 常规输入、移动、回车：P95 ≤ 20 ms，最大 ≤ 50 ms。
- 原始 Esc 单独记录：现有配置 `ttimeoutlen=30` 在本机产生约 60–76 ms 的等待，关闭
  Markdown 同样存在。绝对门槛 P95 ≤ 90 ms、最大 ≤ 110 ms，并报告启用／关闭对照。
  不通过缩短全局终端等待来换取分段方向键／SSH 转义序列的兼容风险。
- 保存包含实际磁盘写入与持久撤销：P95 ≤ 50 ms，最大 ≤ 100 ms。
- 分屏、buffer 切换、阅读切换：P95 ≤ 30 ms，最大 ≤ 80 ms。
- 文件树、目录和显式整理：P95 ≤ 100 ms，最大 ≤ 150 ms。
- Markdown 索引每批预算 3 ms，并限制行数；统计实际最大批次，识别超长行退化。
- 记录启动到可编辑与索引就绪时间；大文件沿用现有保护，不能把关闭全部功能的样本
  冒充正常文档的性能。相同压力样本必须检查编辑结果和代码保护。

索引以 3 ms 为目标预算，验收容许单行处理和调度带来的波动，实际最大批次须 ≤ 8 ms。
真实 SSH 传输和终端物理显示需要用户环境复测。

## 执行记录

- 旧版路径审查完成：内容变更后全文重新规划；插入模式清空、退出恢复装饰；部分上下文
  判断读取大量前文。新版移除这些高频路径，并保留有价值的显式写作操作。
- 显示、共享索引、编辑、导航、离线预览及安装集成均已实现，五个阶段依次完成。
- 经过小文档功能回归、万行／长行压力诊断和多次重复复测，最终验收使用下述完整矩阵。

### 压力测试中的修正

- 第一轮 1200 行交互与功能回归后扩大到万行；索引计时器叠加原始 Esc 等待时，
  退出插入曾达到 110–139 ms。输入期间暂停索引，且共享补全／索引用 `getchar(1)`
  非消费式检查待处理按键，让主循环优先处理输入。长代码块 30 轮复测 P95 为 65.51 ms。
- 文件树获得焦点时暂停索引；返回已有窗口依靠 WinEnter 恢复。补齐真实开关回归，
  避免索引停在半途，命令永久等待。
- 增量解析在状态重新一致时复用后续标题；少量远隔修改可验证前置检查点，避免光标
  返回长代码块时同步扫描全文或误续写。
- 12 万字符连续词暴露共享补全的 `E339: Pattern too long`，并叠加软换行开销。
  自动补全不为超过 1024 字节的输入前缀构建正则，仍保留手动补全和完整长候选；
  Markdown 对超过 8192 字节的单行自动使用横向滚动。该样本三轮输入 P95 为 7.77 ms。
- 补全菜单 Enter 在提交普通输入前单独处理，保留确认候选／未选中换行两种行为。
- 明确的任务／表格命令等待结构就绪，防止待更新文档只整理了部分范围。
- 基准修正软换行的 j/k 判定、用户命令的分隔方式与失败清理，避免测量器掩盖真实错误。
- 密集长行使原生括号匹配与语法着色产生 44–68 ms 的等待。为巨型行增加基础着色、
  横向滚动和自动配对高亮保护；普通行与手动 `%` 保持原有行为。
- 表格整理保留列表内缩进，对规范管道表格直接确认未改变的结构缓存；400 行表格整理后
  的标题跳转不再等待整表重新解析。额外限制输出大小，防止列宽补齐后膨胀。
- 关闭的行内 HTML 注释不再误保护整行任务／表格；未关闭注释和独立注释仍受到保护。
- 重载时暂时隐藏当前辅助窗口，避免恢复其他 Markdown buffer 时触发 `bufhidden=wipe`，
  并验证预览退出、隐藏 buffer、局部映射和窗口选项恢复。
- 本地树首次打开的峰值在关闭 Markdown 的对照组也曾达到 656 ms。定位为 WSL 挂载路径
  上的可选网络工具查找，改为首次实际传输时探测；验证参数、写入范围及原生脚本私有状态。
- TCP 测量通道的延迟确认曾造成约 40 ms 的虚假移动延迟。探针改用 Unix socket；
  这项校准不计为编辑器性能收益。
- 验收复查发现 `getchar(1)` 在 Ex 批处理的 EOF 上会直接结束 Vim，且旧测试助手会将
  没有断言结果的成功退出误计为通过。按键窥视现在跳过命令／Ex 模式；测试每次清除
  旧报告并要求生成新报告，只有“关闭最后一个 buffer”用例显式验证提前退出。
  输入提示取消和终端窗口用例改用真实 PTY，随后重新执行完整回归和时延矩阵。

## 最终时延结果（2026-11-24）

最终完整矩阵 **16 组 × 30 轮全部通过严格门槛**，包含 12 组启用模块、4 组关闭对照，
共 5760 次逐字按键样本；其他操作每组各 30 次。原始数据、首次样本、中位数、P95、
最大值及 34 个源码文件的 SHA-256 见
[最终 JSON](tests/results/markdown-2026-11-24.json)。以下均为本机 Vim 9.1，单位 ms。
混合、标题和表格组在普通任务行输入，长行组在长行输入，代码组在代码块深处输入。
回车列为列表续写，代码块行取代码内回车；长行组的列表回车发生在普通任务行。

| 场景 | 逐字输入 P95 / 最大 | 回车 P95 | 保存 P95 / 最大 |
| --- | ---: | ---: | ---: |
| 1209 行混合文档 | 3.822 / 4.589 | 1.727 | 21.182 / 21.277 |
| 10009 行混合文档 | 4.149 / 4.784 | 1.780 | 19.512 / 19.941 |
| 万行代码块，深处输入与回车 | 4.240 / 4.873 | 3.115 | 22.089 / 22.242 |
| 12 万字符单行，基础配色与横向滚动 | 1.990 / 2.138 | 1.180 | 21.088 / 21.243 |
| 12.6 万字符密集行内标记，使用长行保护 | 3.149 / 4.033 | 1.167 | 21.368 / 21.444 |
| 400 行表格 | 1.847 / 2.308 | 1.774 | 20.240 / 20.425 |
| 万行混合文档，预览服务与同步开启 | 4.217 / 8.178 | 1.851 | 20.810 / 20.819 |
| 60009 行、约 708 KiB，预览服务与同步开启 | 4.169 / 4.827 | 1.556 | 23.900 / 24.338 |

万行密集标题／表格另有独立场景，逐字输入 P95 分别为 4.247／4.122 ms。
20／80 ms 按键间隔场景的输入 P95 为 5.596／7.137 ms；启用模块的所有场景中，
逐字输入最大值为 9.437 ms，索引实际最长批次为 4.104 ms，普通编辑上下文回退次数为 0。

400 行表格显式整理 P95／最大为 55.612／57.457 ms，紧接着的标题跳转 P95 为
1.237 ms。密集标题目录打开 P95 为 9.088 ms；首次文件树打开最大为 20.728 ms。
文件树目录很小，此处衡量 Markdown 与树的切换，万文件树的完整就绪成本见既有性能记录。

| 万行混合文档对照 | 逐字输入 P95 | 原始 Esc P95 |
| --- | ---: | ---: |
| 开启 Markdown | 4.149 | 66.374 |
| 关闭 Markdown | 4.312 | 62.697 |

保留原有 `ttimeoutlen=30`；原始 Esc 等待单独验收。测得的接近值不用于声称微小的
输入速度提升，关闭对照主要确认新版没有增加明显的逐键开销。

| 初次打开 | 首个普通模式重绘（ms） | 完整索引就绪（ms） | 最长主循环探针间隔（ms） |
| --- | ---: | ---: | ---: |
| 1209 行混合文档 | 29.064 | 191.353 | 21.176 |
| 10009 行混合文档 | 27.265 | 1321.521 | 20.092 |
| 60009 行混合文档，预览组 | 29.601 | 7827.648 | 24.312 |

索引就绪时间从进程启动计算，首帧与完整索引是两个指标。全矩阵最长探针间隔为
53.512 ms，发生于显式大表格整理；索引的约 3 ms 预算不代表整个主循环的固定上限。
JSON 另列本机系统 netrw 初始化留下的 `E31: No such mapping`，该信息没有计作
Markdown 文本处理异常。

## 功能验收

系统 Vim 9.1 与独立编译的 Vim 8.2.5172，各 350 项完整回归通过；两次均启用真实
Chrome 测试。Vim 8.2 构建没有 `+python3`，编辑与预览均不依赖 Vim 的 Python 接口。

覆盖源码与撤销不受渲染影响、列表／代码保护、补全确认与换行、中文选区与表格、
重复锚点、未保存内容、目录失效、随机编辑后增量／完整解析一致性，以及窗口选项、
隐藏 buffer、重载、禁用、安装升级与符号链接目标保护。浏览器验证离线公式、代码、
表格、任务、提示块与后续未保存快照的刷新，HTTP 用例验证图片路径和资产边界。

## 保存峰值复核

一轮完整矩阵在长代码块保存时出现 **318.522 ms**，该组保存 P95 为 23.079 ms，
使那次严格验收失败。原始数据保存在
[失败矩阵](tests/results/markdown-2026-11-24-save-outlier.json)，其余 15 组通过。

追加同一万行长代码块的两组 100 轮专项，使用
[fsync_probe.c](tests/fsync_probe.c) 计时实际 libc `fsync`，保持原生磁盘同步与持久撤销：

| 模块 | 保存 P95 / 最大（ms） | 实际 fsync 次数 | fsync 最大（ms） | 严格验收 |
| --- | ---: | ---: | ---: | --- |
| 开启 | 19.965 / 22.840 | 201 | 12.465 | 通过 |
| 关闭 | 21.994 / 23.471 | 201 | 12.728 | 通过 |

402 次同步全部成功。两组复测未重现原始峰值，具体原因仍未确定，因此**不能声称保存
始终低于 100 ms**。专项数据与逐次系统调用记录见
[开启 JSON](tests/results/markdown-2026-11-24-fsync-enabled.json)、
[关闭 JSON](tests/results/markdown-2026-11-24-fsync-disabled.json)、
[开启 trace](tests/results/markdown-2026-11-24-fsync-enabled.tsv)、
[关闭 trace](tests/results/markdown-2026-11-24-fsync-disabled.tsv)。最终矩阵的通过表示那轮
实测达到门槛，早先的异常仍保留为已知限制。

## 复测

在仓库根目录运行，性能基准与其他测试串行执行：

```bash
# 完整功能回归；默认跳过真实浏览器。
python3 vim/tests/run.py

# 需要已安装 Google Chrome，或用 VIM_MARKDOWN_CHROME 指定兼容的可执行文件。
VIM_MARKDOWN_BROWSER_TEST=1 python3 vim/tests/run.py

# 固定 16 组场景，每组 30 轮，任一硬门槛失败时返回非零。
python3 vim/tests/markdown_latency.py --matrix --rounds 30 --strict \
  --output vim/tests/results/markdown-local.json

# 单独复测长代码块、真实输入间隔与模块关闭对照。
python3 vim/tests/markdown_latency.py --case long-code --lines 10000 \
  --rounds 30 --key-delay-ms 80 --strict
python3 vim/tests/markdown_latency.py --case mixed --lines 10000 \
  --rounds 30 --disabled --strict

# Linux 保存诊断，可选；探针计时原生 fsync，不改变磁盘同步语义。
cc -O2 -Wall -Wextra -shared -fPIC -o /tmp/vim-fsync-probe.so \
  vim/tests/fsync_probe.c -ldl
LD_PRELOAD=/tmp/vim-fsync-probe.so VIM_FSYNC_TRACE=/tmp/vim-fsync.tsv \
  python3 vim/tests/markdown_latency.py --case long-code --lines 10000 \
  --rounds 100 --strict

# 直接试用仓库配置。
vim -Nu vim/.vimrc vim/markdown/example.md
```

旧版 Vim 测试可设置 `VIM_TEST_BINARY`；未安装的源码构建同时设置 `VIMRUNTIME`。

## 实际边界

- 交互矩阵在首次索引完成后运行，启动与索引就绪另列。初次打开长文档时，尚未建立
  上下文的区域使用原生 Enter；导航等结构命令异步等待，继续编辑可取消旧请求。
- 高亮默认检查每行前 512 字节、向前同步最多 120 行；长代码块深处可能只有基础配色。
  编辑保护使用独立索引。超过 8192 字节的单行使当前文档使用基础配色与横向滚动，
  缩短后恢复。≥ 1 MiB 或 Markdown 超过十万行时，使用已有的 text 快速模式。
- 表格按命令整理，限制 500 行、40 列，输入／输出各 ≤ 64 KiB。数学、图片与图表保留
  源码；公式在浏览器渲染，Mermaid／PlantUML 仅提供模板，不常驻图表引擎。
- 预览在停止输入 250 ms 后合并更新，快照上限 1 MiB，一次只保留一个在途请求。
  预览时延矩阵使用 `VimMarkdownPreview!` 测量服务和同步；浏览器渲染正确性单独验证，
  不把它当作六万行浏览器绘制速度的测量。
- 数据来自本机 Linux/WSL2、100×30 的真实 PTY，关闭 LSP、剪贴板传输及个人钩子。
  测到 Vim 状态与重绘完成，不包括 SSH 网络、用户终端与物理显示器刷新。
